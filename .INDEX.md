## Dr.Debug repositories

- `doktor-debug/.github` — public organization profile source
- `doktor-debug/.agents` — global governance, agent instructions, modes, gates, routing, and task directives
- `doktor-debug/.api` — Dr.Debug domain API contracts, schemas, handlers/adapters, and contract tests for `/doktor-debug/**`
- `doktor-debug/.archive` — active preservation and provenance
- `doktor-debug/.canonical` — verified reusable diagnostic knowledge
- `doktor-debug/.import` — controlled extraction and import staging
- `doktor-debug/.memory` — accepted observations with evidence, scope, and lifecycle state
- `doktor-debug/.proposals` — hypotheses, unconfirmed fixes, and proposed structural changes
- `doktor-debug/.research` — sources, claims, conflicts, provenance, and evidence analysis
- `doktor-debug/.scanner` — untrusted artifact intake and triage; never execute intake artifacts
- `doktor-debug/.storage` — payload retention, integrity, controlled delivery, and retention metadata
- `doktor-debug/.taxonomy` — authoritative Dr.Debug classification and routing taxonomy
- `doktor-debug/.web` — private presentation/source repository
- `doktor-debug/.workflows` — reproducible repair, validation, migration, and rollback workflows
- `doktor-debug/wiki` — public documentation portal
- `doktor-debug/doktor-debug.github.io` — designated sanitized public-release target; publication is deliberate, not implicit

## Shared gateway/control plane

- `n-e-o-w-u-l-f/.myAPI` — shared gateway responsibilities such as `/`, shared health/system endpoints, cross-project discovery, authentication and owner resolution, audit, dispatch, and common enforcement.

The shared gateway must not duplicate Dr.Debug domain ownership. Dr.Debug-specific contracts under `/doktor-debug/**` belong to `doktor-debug/.api`.

## Evidence and authority

Authority mode and evidence state are independent dimensions.

Authority modes: `CUSTOMER_MODE`, `ADMIN_MODE`, `OWNER_MODE`.

Knowledge/evidence states: `draft`, `candidate`, `validated`, `canonical`, `superseded`, `rejected`.

Authority never proves a hypothesis, and a successful repair command never proves a fix. `VERIFY_FIX` must retest the original failure condition before a repair can be treated as verified.
